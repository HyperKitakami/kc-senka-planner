# UI 设计（UI Design）

## 文档说明

本文档用于定义 Kancolle Senka Planner 的整体界面架构、页面职责与交互原则。

本文档仅描述页面布局与功能分区，不涉及具体样式、颜色、组件实现及业务逻辑。

---

# 一、设计目标

界面设计应遵循以下原则：

* 本地工具优先，强调长期使用体验。
* 首页快速获取信息，减少操作步骤。
* 录入数据简单快捷。
* 浏览历史数据方便清晰。
* 统计分析与数据录入分离。
* 保持良好的扩展性，新增功能无需重新设计整体布局。

---

# 二、整体布局

采用后台管理（Dashboard）式布局。

```
┌──────────────┬────────────────────────────────────┐
│              │                                    │
│ 左侧导航栏    │            主工作区                 │
│              │                                    │
│              │                                    │
│              │                                    │
│              │                                    │
│              │                                    │
│              │                                    │
└──────────────┴────────────────────────────────────┘
```

左侧导航栏负责页面切换。

主工作区负责当前页面内容展示。

整体布局应保持统一，不因页面切换改变整体结构。

---

# 三、导航栏

建议采用固定左侧导航。

导航项目如下：

* 首页
* 周期查询
* 战果记录
* 战果规划
* 战果任务
* 数据分析
* 历史归档
* 数据管理
* 设置

导航顺序按照日常使用频率设计，而非开发顺序。

未来新增功能应优先以新增页面形式扩展。

---

# 四、页面职责

## 4.1 首页（Dashboard）

首页作为整个工具的总览页面。

用户打开工具后默认进入首页。

首页主要用于快速了解当前状态，不承担复杂编辑功能。

首页建议展示：

* 当前战果
* 当前目标
* 目标完成率
* 预计月底战果
* 所需平均每日战果
* 当前实际平均每日战果
* 最近数据摘要
* 周期剩余时间

首页仅允许少量快捷操作。

复杂编辑应进入对应页面完成。

---

## 4.2 周期查询

只读的时间边界速查页，回答两个问题：任务什么时候刷新、战果什么时候结算。

由于项目存在**两套互不混用的时间边界**（docs/03_data.md §七），本页必须把它们
**分块并列展示**，不得合并成一张"周期表"，以免使用者误以为只有一个边界。

**任务更新周期**（任务刷新边界，一律 04:00）：

* 日常 / 周常 / 月常 / 季常：当前周期编号、起算与结束时刻、周期长度、剩余时间
* 年常：起算月份由**用户添加的年常任务**决定，一个起算月份一个区间
  （如 6 月起算即 6 月 1 日 04:00 ～ 次年 6 月 1 日 04:00）；
  同为一个月起算的多个年常任务属**同一周期**，只列出一个区间，不得重复计算；
  停用的年常任务不产生区间；没有年常任务时不显示年常行
* 活动 / 期间限定：由用户手动开始与结束，没有可计算的边界，只作说明

**战果结算周期**（战果归属边界）：

* 出击战果 / EO 战果：结算于本月末日 **21:00**
* 任务战果：结算于本月末日 **13:00**
* 分别显示当前归属月、结算时刻与剩余时间
* EO 血条复活时刻（本月末日 **23:00**）
* 处于归属切换窗口（本月末日 13:00 ～ 21:00）时给出提示
* 当前归属月为季度第三月（2 / 5 / 8 / 11 月）时给出季常战果失效警告

本页所有数值均为运行时计算，**不写入任何数据**；不提供编辑操作。

---

## 4.3 战果记录

负责每日战果数据录入。

主要功能包括：

* 新增记录
* 修改记录
* 删除记录
* 勾选标记已规划完成的任务等奖励战果
* 查看历史记录

该页面以数据录入效率为优先。

页面应支持两种录入模式（页头切换，选择记入 Settings）：

* **列表模式**：新增 / 修改表单 + 本月记录表格（默认）
* **日历模式**：月历表格，格子里直接输入当日出击战果；
  回车跳到下一格并自动保存，Tab 按日期顺序前进；清空格子即删除该日记录。
  未来日期不开放录入（出击战果是已发生的事实）。

日历模式下写入后只刷新汇总数字，不重建网格，以保证可以连续录入。

### 4.3.1 poi 数据同步

页面提供「poi 数据同步」面板，从外部战果插件的数据文件中读取当日建议值。

该面板采用**两步操作**：

1. **选择数据文件**：手动选取 poi 的数据文件，解析后把该月建议值展示出来。
   面板显示数据来源与同步时间，便于判断数据的新旧。
2. **一键填充空白项**：用户确认后，仅把建议值写入**尚无记录**的日期。
   已有记录一律跳过，绝不覆盖。

面板需说明：

* 建议值口径为「每日仅出击 + 演习战果」，与本站 DailyRecord 一致，不含 EO / 任务战果。
* 浏览器不允许网页自行读取本地路径，必须由用户手动选取文件；面板应给出参考路径。
* poi 侧数据跨月会被覆盖，因此同步结果以快照形式留存在本机（见 docs/03_data.md §9.1）。

**同步完全由用户手动触发，程序启动时不会自动同步，也不提供定时同步。**

---

## 4.4 战果规划

负责目标设定与规划计算。

主要展示：

* 当前目标
* 剩余目标
* 当前平均每日出击战果（自然日均）
* 所需平均每日出击战果（基于目标与规划池）
* 预计月底战果（默认基于最近7天平均）

支持切换不同展示口径（仅影响显示，不影响数据存储）：

* 实际统计口径
* 综合进度口径（可选，含规划任务）

切换后应实时更新全部规划结果。

页面应支持切换「战果归属月」，用于补录历史月份的继承战果与月目标；
所看月份已归档时，保存前必须显式确认。

---

## 4.5 战果任务

负责管理所有战果来源任务。

包括但不限于：

* EO
* EX
* 活动任务

每项任务应展示：

* 名称
* 当前状态
* 战果值
* 当前周期
* 是否参与规划

该页面应支持快速完成或取消完成任务。

页面应支持切换「战果归属月」，以补录任意历史周期的任务完成状态；
日常 / 周常一个月内有多个周期，应支持逐期选择后再标记完成。
所看月份已归档时，写入前必须显式确认。

任务按「任务组」分卡片展示，并额外提供：

* **预设 EX 任务卡片**：位于 EO 卡片正下方，单独成卡片，收纳内置的固定 EX 任务
  （季常 / 年常）。卡片内嵌 poi 季常同步区（§4.5.2）。
* 名称列显示**游戏内完整任务名**，简称作为悬停提示保留 —— 简称便于识记，
  完整名称便于确认是游戏里的哪一条任务。

带进度节点的任务：

* 列表中应显示进度角标（已达成节点数 / 总节点数），默认折叠，可**行内展开**逐项记录进度。
* 已完成的任务其节点操作应锁定，需先取消完成才能继续调整（取消完成后进度保留）。
* 取消完成时若节点已全部达成，应先提示将一并重置进度，经用户确认后再执行。
* 新增 / 编辑任务的表单应提供节点编辑区，可增删节点并分别设置代号、说明与需要次数；
  系统任务不提供该编辑区。

### 4.5.1 poi EO 批量同步

页面提供「poi EO 同步」面板（位于 EO 卡片正上方），把外部战果插件的 EO 完成状态与本工具比对。
（EX 任务的同步是另一块，见 §4.5.2。）

* 列出 poi 侧已完成、但本工具尚未标记的 EO，供用户**批量确认**标记完成。
* 反向差异（本工具已标记完成、poi 侧未完成）**仅作提示，不自动取消**；
  原因见 docs/04_calculation.md §13.1.5。
* 补录历史月份时，同步结果写入**该归属月**对应周期。

同步同样**只能手动触发**，且依赖该月已保存的 poi 快照（在战果记录页同步产生）。

### 4.5.2 poi EX 季常同步

预设 EX 任务卡片内提供「poi 季常同步」区，把 poi 侧的**季常**完成状态与本工具比对。

* 列出 poi 侧**在当前战果月内**已完成、但本工具尚未标记的季常任务，供用户**批量确认**标记完成。
* 反向差异（本工具已标记完成、poi 侧未完成）**仅作提示，不自动取消**；
  原因见 docs/04_calculation.md §13.1.5。
* 补录历史月份时，同步结果写入**该归属月**对应周期。

范围与限制：

* **只同步季常。** 年常（AL / 机动等）poi 侧没有完成标记，需在卡片列表里手动勾选。
* 用户自建的 EX 任务同样不参与同步。
* 名称匹配依据模板上的 `poiName` 字段，而非界面显示的任务名
  （见 docs/03_data.md §2.2、docs/04_calculation.md §13.1.6）。
* poi 清单里出现、本工具不跟踪的季常项会被忽略，不影响卡片其它功能。
* poi 侧清单**每个战果月重置**，只记录该战果月内完成的项 —— 本季更早月份完成的季常
  不会出现在待勾选列表里，需自行核对后手动勾选。

同步同样**只能手动触发**，且依赖该月已保存的 poi 快照（在战果记录页同步产生）。

---

## 4.6 数据分析

负责展示统计数据。

包括但不限于：

* 每日增长趋势
* 战果变化趋势
* 月度统计
* 历史统计
* 不同月份比较

该页面主要用于分析，不承担数据编辑功能。

「月度比较」卡片支持勾选要纳入比较的数据（继承战果 / 出击战果 / EO 战果 / 任务战果），
横轴区间可自由选择起止月份，最长 24 个月、最短 1 个月（超长自动截断并提示）。
其分段颜色必须与「战果构成」卡片一致；两项选择均记入 Settings。

### 4.6.1 战果线对比

本页提供「战果线对比」卡片，以折线图展示当月战果线（联合 / 一群 / 二群 / 三群）
与自身累计战果的走势对比。

* 数据来自本机保存的 poi 快照；该月没有快照时，卡片给出引导提示而不绘制空图。
* 自身累计线优先采用 poi 侧口径，缺失时回退为当月 DailyRecord 的逐日累计。
* 数据缺失的日期连线断开，不伪造数值。

---

## 4.7 历史归档

负责查看历史月份数据。

包括：

* 每月最终战果（用户录入的末日 21:00 结算快照）
* 计算战果（按该月原始记录实时计算，与最终战果独立并列展示）
* 计算战果与最终战果的差值
* 最终奖励区间
* 官方对应奖励线（可选记录）
* 与奖励线差值
* 奖励内容
* 人事表（按归档月份与所在服务器自动生成图片地址）
* 月度备注

新建 / 编辑归档时，计算战果应直接作为只读字段展示，不得覆盖最终战果。
计算战果不写入 Archive；原始记录变化后应实时更新。

支持长期查询。

归档记录列表支持分页显示，单页显示数量可选 10 / 20 / 50（选择记入 Settings，默认 10）。
归档记录列表支持按年份与奖励区间筛选；筛选只作用于列表，统计卡仍按全量计算。

---

## 4.8 数据管理

负责所有数据管理功能。

包括：

* 自动保存状态
* 导出数据
* 导入数据
* 数据备份
* 数据恢复

原则上不放置业务功能。

---

## 4.9 设置

负责程序配置。

例如：

* 外观
* 首页显示内容（顺序、尺寸、显示 / 隐藏）
* 默认规划方式
* 游戏服务器（用于生成人事表图片地址）
* 数据相关设置
* 其它偏好设置

其中「poi 数据快照」用于管理本机保存的 poi 快照：

* 展示已保存快照的月份、最近同步时间与来源文件。
* 提供清除入口，可一次清除全部快照。
* 清除前必须显式确认，并说明**只清除 poi 快照，不影响任何业务数据**，
  且该内容不属于导出范围。

# 五、首页设计原则

首页定位为 Dashboard。

目标是在最短时间内提供最重要的信息。

首页不应承担大量编辑工作。

首页推荐采用卡片（Widget）布局。

每张卡片负责展示一种信息。

例如：

* 当前战果
* 目标完成率
* 今日增长
* 最近趋势
* 预计月底
* 所需日均

未来允许用户：

* 显示或隐藏卡片
* 调整卡片顺序（首页「编辑布局」模式下拖动，或设置页上下移）
* 调整卡片大小（小 / 中 / 大，决定卡片在网格里跨几列）

布局的两条约定：

* **必须进入编辑模式**才能拖动排序或改尺寸。首页平时是纯展示的，避免误触，
  也避免拖拽和卡片内的点击相互干扰。设置页另有一套等价的控件（顺序、尺寸、
  显示 / 隐藏），用于键盘 / 触屏操作。
* 卡片大小用**列跨度**表达，不写死像素：网格列数由可用宽度算出（1 ～ 4 列），
  窄屏下大号会退化成整行，因此不会溢出错行。统计卡与面板卡处在同一个网格里，
  面板卡也可以拖到任意位置、也可以缩小。

新增功能时，应优先增加新卡片，而非修改首页整体布局。

---

# 六、可视化设计

可视化用于辅助理解数据，不作为唯一信息来源。

首页仅展示概览级图表。

例如：

* 完成率
* 最近增长趋势
* 目标进度

完整统计图应放置于「数据分析」页面。

未来可扩展：

* 折线图
* 柱状图
* 占比图
* 月度比较图
* 年度趋势图

---

# 七、交互原则

所有计算结果应实时更新。

用户修改数据后：

* 页面无需刷新。
* 当前页面立即更新。
* 所有关联统计同步更新。
* 自动保存数据。

删除、覆盖等重要操作应提供确认提示。

外部数据同步（poi 数据）一律**由用户手动触发**：程序不自动读取本地文件，
不在启动时同步，也不提供定时同步。外部数据写入业务数据前必须经用户确认。

---

# 八、响应式设计

优先支持桌面浏览器。

最低支持 1920×1080 显示环境。

较小窗口允许滚动浏览。

移动端仅保证基础浏览能力，不作为主要使用场景。

---

# 九、未来扩展

整体布局应支持未来新增页面。

例如：

* 数据预测
* 多账号管理
* 外部数据同步
* 更多统计分析

新增页面不应影响现有导航结构与页面职责。
