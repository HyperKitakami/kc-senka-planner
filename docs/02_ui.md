# UI 设计（UI Design）

## 文档说明

本文档用于定义 Kancolle Senka Planner 的整体界面架构、页面职责与交互原则。

本文档仅描述页面布局与功能分区，不涉及具体样式、颜色、组件实现及业务逻辑。

---

# 一、设计目标

界面设计应遵循以下原则：

* 本地工具优先，强调长期使用体验。
* 首页快速获取信息，减少操作步骤。
* 录入数据简单快捷。
* 浏览历史数据方便清晰。
* 统计分析与数据录入分离。
* 保持良好的扩展性，新增功能无需重新设计整体布局。

---

# 二、整体布局

采用后台管理（Dashboard）式布局。

```
┌──────────────┬────────────────────────────────────┐
│              │                                    │
│ 左侧导航栏    │            主工作区                 │
│              │                                    │
│              │                                    │
│              │                                    │
│              │                                    │
│              │                                    │
│              │                                    │
└──────────────┴────────────────────────────────────┘
```

左侧导航栏负责页面切换。

主工作区负责当前页面内容展示。

整体布局应保持统一，不因页面切换改变整体结构。

---

# 三、导航栏

建议采用固定左侧导航。

导航项目如下：

* 首页
* 战果记录
* 战果规划
* 战果任务
* 数据分析
* 历史归档
* 数据管理
* 设置

导航顺序按照日常使用频率设计，而非开发顺序。

未来新增功能应优先以新增页面形式扩展。

---

# 四、页面职责

## 4.1 首页（Dashboard）

首页作为整个工具的总览页面。

用户打开工具后默认进入首页。

首页主要用于快速了解当前状态，不承担复杂编辑功能。

首页建议展示：

* 当前战果
* 当前目标
* 目标完成率
* 预计月底战果
* 所需平均每日战果
* 当前实际平均每日战果
* 最近数据摘要
* 周期剩余时间

首页仅允许少量快捷操作。

复杂编辑应进入对应页面完成。

---

## 4.2 战果记录

负责每日战果数据录入。

主要功能包括：

* 新增记录
* 修改记录
* 删除记录
* 勾选标记已规划完成的任务等奖励战果
* 查看历史记录

该页面以数据录入效率为优先。

---

## 4.3 战果规划

负责目标设定与规划计算。

主要展示：

* 当前目标
* 剩余目标
* 当前平均每日出击战果（自然日均）
* 所需平均每日出击战果（基于目标与规划池）
* 预计月底战果（默认基于最近7天平均）

支持切换不同展示口径（仅影响显示，不影响数据存储）：

* 实际统计口径
* 综合进度口径（可选，含规划任务）

切换后应实时更新全部规划结果。

---

## 4.4 战果任务

负责管理所有战果来源任务。

包括但不限于：

* EO
* EX
* 活动任务

每项任务应展示：

* 名称
* 当前状态
* 战果值
* 当前周期
* 是否参与规划

该页面应支持快速完成或取消完成任务。

---

## 4.5 数据分析

负责展示统计数据。

包括但不限于：

* 每日增长趋势
* 战果变化趋势
* 月度统计
* 历史统计
* 不同月份比较

该页面主要用于分析，不承担数据编辑功能。

---

## 4.6 历史归档

负责查看历史月份数据。

包括：

* 每月最终战果
* 最终奖励区间
* 官方对应奖励线（可选记录）
* 与奖励线差值
* 奖励内容
* 月度备注

支持长期查询。

---

## 4.7 数据管理

负责所有数据管理功能。

包括：

* 自动保存状态
* 导出数据
* 导入数据
* 数据备份
* 数据恢复

原则上不放置业务功能。

---

## 4.8 设置

负责程序配置。

例如：

* 外观
* 首页显示内容
* 默认规划方式
* 数据相关设置
* 其它偏好设置

---

# 五、首页设计原则

首页定位为 Dashboard。

目标是在最短时间内提供最重要的信息。

首页不应承担大量编辑工作。

首页推荐采用卡片（Widget）布局。

每张卡片负责展示一种信息。

例如：

* 当前战果
* 目标完成率
* 今日增长
* 最近趋势
* 预计月底
* 所需日均

未来允许用户：

* 显示或隐藏卡片
* 调整卡片顺序

新增功能时，应优先增加新卡片，而非修改首页整体布局。

---

# 六、可视化设计

可视化用于辅助理解数据，不作为唯一信息来源。

首页仅展示概览级图表。

例如：

* 完成率
* 最近增长趋势
* 目标进度

完整统计图应放置于「数据分析」页面。

未来可扩展：

* 折线图
* 柱状图
* 占比图
* 月度比较图
* 年度趋势图

---

# 七、交互原则

所有计算结果应实时更新。

用户修改数据后：

* 页面无需刷新。
* 当前页面立即更新。
* 所有关联统计同步更新。
* 自动保存数据。

删除、覆盖等重要操作应提供确认提示。

---

# 八、响应式设计

优先支持桌面浏览器。

最低支持 1920×1080 显示环境。

较小窗口允许滚动浏览。

移动端仅保证基础浏览能力，不作为主要使用场景。

---

# 九、未来扩展

整体布局应支持未来新增页面。

例如：

* 数据预测
* 多账号管理
* POI 数据导入
* 外部数据同步
* 更多统计分析

新增页面不应影响现有导航结构与页面职责。
