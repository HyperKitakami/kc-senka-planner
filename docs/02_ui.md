# UI 设计（UI Design）

## 文档说明

本文档用于定义 Kancolle Senka Planner 的整体界面架构、页面职责与交互原则。

本文档仅描述页面布局与功能分区，不涉及具体样式、颜色、组件实现及业务逻辑。

---

# 一、设计目标

界面设计应遵循以下原则：

* 本地工具优先，强调长期使用体验。
* 首页快速获取信息，减少操作步骤。
* 录入数据简单快捷。
* 浏览历史数据方便清晰。
* 统计分析与数据录入分离。
* 保持良好的扩展性，新增功能无需重新设计整体布局。

---

# 二、整体布局

采用后台管理（Dashboard）式布局。

```
┌──────────────┬────────────────────────────────────┐
│              │                                    │
│ 左侧导航栏    │            主工作区                 │
│              │                                    │
│              │                                    │
│              │                                    │
│              │                                    │
│              │                                    │
│              │                                    │
└──────────────┴────────────────────────────────────┘
```

左侧导航栏负责页面切换。

主工作区负责当前页面内容展示。

整体布局应保持统一，不因页面切换改变整体结构。

---

# 三、导航栏

建议采用固定左侧导航。

导航项目如下：

* 首页
* 周期查询
* 战果记录
* 战果规划
* 战果任务
* 数据分析
* 历史归档
* 数据管理
* 设置

导航顺序按照日常使用频率设计，而非开发顺序。

未来新增功能应优先以新增页面形式扩展。

---

# 四、页面职责

## 4.1 首页（Dashboard）

首页作为整个工具的总览页面。

用户打开工具后默认进入首页。

首页主要用于快速了解当前状态，不承担复杂编辑功能。

首页建议展示：

* 当前战果
* 当前目标
* 目标完成率
* 预计月底战果
* 所需平均每日战果
* 当前实际平均每日战果
* 最近数据摘要
* 周期剩余时间

首页仅允许少量快捷操作。

复杂编辑应进入对应页面完成。

---

## 4.2 周期查询

只读的时间边界速查页，回答两个问题：任务什么时候刷新、战果什么时候结算。

由于项目存在**两套互不混用的时间边界**（docs/03_data.md §七），本页必须把它们
**分块并列展示**，不得合并成一张"周期表"，以免使用者误以为只有一个边界。

**任务更新周期**（任务刷新边界，一律 04:00）：

* 日常 / 周常 / 月常 / 季常：当前周期编号、起算与结束时刻、周期长度、剩余时间
* 年常：起算月份由**用户添加的年常任务**决定，一个起算月份一个区间
  （如 6 月起算即 6 月 1 日 04:00 ～ 次年 6 月 1 日 04:00）；
  同为一个月起算的多个年常任务属**同一周期**，只列出一个区间，不得重复计算；
  停用的年常任务不产生区间；没有年常任务时不显示年常行
* 活动 / 期间限定：由用户手动开始与结束，没有可计算的边界，只作说明

**战果结算周期**（战果归属边界）：

* 出击战果 / EO 战果：结算于本月末日 **21:00**
* 任务战果：结算于本月末日 **13:00**
* 分别显示当前归属月、结算时刻与剩余时间
* EO 血条复活时刻（本月末日 **23:00**）
* 处于归属切换窗口（本月末日 13:00 ～ 21:00）时给出提示
* 当前归属月为季度第三月（2 / 5 / 8 / 11 月）时给出季常战果失效警告

本页所有数值均为运行时计算，**不写入任何数据**；不提供编辑操作。

---

## 4.3 战果记录

负责每日战果数据录入。

主要功能包括：

* 新增记录
* 修改记录
* 删除记录
* 勾选标记已规划完成的任务等奖励战果
* 查看历史记录

该页面以数据录入效率为优先。

页面应支持两种录入模式（页头切换，选择记入 Settings）：

* **列表模式**：新增 / 修改表单 + 本月记录表格（默认）
* **日历模式**：月历表格，格子里直接输入当日出击战果；
  回车跳到下一格并自动保存，Tab 按日期顺序前进；清空格子即删除该日记录。
  未来日期不开放录入（出击战果是已发生的事实）。

日历模式下写入后只刷新汇总数字，不重建网格，以保证可以连续录入。

---

## 4.4 战果规划

负责目标设定与规划计算。

主要展示：

* 当前目标
* 剩余目标
* 当前平均每日出击战果（自然日均）
* 所需平均每日出击战果（基于目标与规划池）
* 预计月底战果（默认基于最近7天平均）

支持切换不同展示口径（仅影响显示，不影响数据存储）：

* 实际统计口径
* 综合进度口径（可选，含规划任务）

切换后应实时更新全部规划结果。

页面应支持切换「战果归属月」，用于补录历史月份的继承战果与月目标；
所看月份已归档时，保存前必须显式确认。

---

## 4.5 战果任务

负责管理所有战果来源任务。

包括但不限于：

* EO
* EX
* 活动任务

每项任务应展示：

* 名称
* 当前状态
* 战果值
* 当前周期
* 是否参与规划

该页面应支持快速完成或取消完成任务。

页面应支持切换「战果归属月」，以补录任意历史周期的任务完成状态；
日常 / 周常一个月内有多个周期，应支持逐期选择后再标记完成。
所看月份已归档时，写入前必须显式确认。

---

## 4.6 数据分析

负责展示统计数据。

包括但不限于：

* 每日增长趋势
* 战果变化趋势
* 月度统计
* 历史统计
* 不同月份比较

该页面主要用于分析，不承担数据编辑功能。

---

## 4.7 历史归档

负责查看历史月份数据。

包括：

* 每月最终战果（用户录入的末日 21:00 结算快照）
* 计算战果（按该月原始记录实时计算，与最终战果独立并列展示）
* 计算战果与最终战果的差值
* 最终奖励区间
* 官方对应奖励线（可选记录）
* 与奖励线差值
* 奖励内容
* 人事表（按归档月份与所在服务器自动生成图片地址）
* 月度备注

新建 / 编辑归档时，计算战果应直接作为只读字段展示，不得覆盖最终战果。
计算战果不写入 Archive；原始记录变化后应实时更新。

支持长期查询。

归档记录列表支持分页显示，单页显示数量可选 10 / 20 / 50（选择记入 Settings，默认 10）。

---

## 4.8 数据管理

负责所有数据管理功能。

包括：

* 自动保存状态
* 导出数据
* 导入数据
* 数据备份
* 数据恢复

原则上不放置业务功能。

---

## 4.9 设置

负责程序配置。

例如：

* 外观
* 首页显示内容（顺序、尺寸、显示 / 隐藏）
* 默认规划方式
* 游戏服务器（用于生成人事表图片地址）
* 数据相关设置
* 其它偏好设置

---

# 五、首页设计原则

首页定位为 Dashboard。

目标是在最短时间内提供最重要的信息。

首页不应承担大量编辑工作。

首页推荐采用卡片（Widget）布局。

每张卡片负责展示一种信息。

例如：

* 当前战果
* 目标完成率
* 今日增长
* 最近趋势
* 预计月底
* 所需日均

未来允许用户：

* 显示或隐藏卡片
* 调整卡片顺序（首页「编辑布局」模式下拖动，或设置页上下移）
* 调整卡片大小（小 / 中 / 大，决定卡片在网格里跨几列）

布局的两条约定：

* **必须进入编辑模式**才能拖动排序或改尺寸。首页平时是纯展示的，避免误触，
  也避免拖拽和卡片内的点击相互干扰。设置页另有一套等价的控件（顺序、尺寸、
  显示 / 隐藏），用于键盘 / 触屏操作。
* 卡片大小用**列跨度**表达，不写死像素：网格列数由可用宽度算出（1 ～ 4 列），
  窄屏下大号会退化成整行，因此不会溢出错行。统计卡与面板卡处在同一个网格里，
  面板卡也可以拖到任意位置、也可以缩小。

新增功能时，应优先增加新卡片，而非修改首页整体布局。

---

# 六、可视化设计

可视化用于辅助理解数据，不作为唯一信息来源。

首页仅展示概览级图表。

例如：

* 完成率
* 最近增长趋势
* 目标进度

完整统计图应放置于「数据分析」页面。

未来可扩展：

* 折线图
* 柱状图
* 占比图
* 月度比较图
* 年度趋势图

---

# 七、交互原则

所有计算结果应实时更新。

用户修改数据后：

* 页面无需刷新。
* 当前页面立即更新。
* 所有关联统计同步更新。
* 自动保存数据。

删除、覆盖等重要操作应提供确认提示。

---

# 八、响应式设计

优先支持桌面浏览器。

最低支持 1920×1080 显示环境。

较小窗口允许滚动浏览。

移动端仅保证基础浏览能力，不作为主要使用场景。

---

# 九、未来扩展

整体布局应支持未来新增页面。

例如：

* 数据预测
* 多账号管理
* POI 数据导入
* 外部数据同步
* 更多统计分析

新增页面不应影响现有导航结构与页面职责。
