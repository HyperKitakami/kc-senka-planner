# 计算规则（Calculation Rules）

## 文档说明

本文档用于定义 Kancolle Senka Planner 的业务计算规则。

本文档描述：

* 数据如何计算
* 不同数据之间的关系
* 周期如何判定
* 规划如何计算
* 预测如何计算

本文档不涉及具体程序实现。

---

# 一、计算原则

## 1.1 单一计算来源

所有统计结果均应由原始数据实时计算。

程序不得保存任何统计结果。

包括但不限于：

* 日均战果
* 完成率
* 预计月底战果
* 图表数据
* 排序结果

所有结果均应根据当前数据重新计算。

---

## 1.2 实时更新

任意原始数据发生变化后：

* 当前页面立即更新
* 所有关联统计同步更新
* 图表同步更新
* 自动保存

程序不得保留旧计算结果。

---

## 1.3 历史优先

程序允许补录、修改历史数据。

任何历史数据修改后，应重新计算全部统计结果。

程序不得因当前日期限制历史数据修改。

---

# 二、战果组成

系统中的"战果"均指当前统计周期内的累计战果。

总战果组成如下：

```text
总战果
=
继承战果
+
累计出击战果
+
已完成 EO 战果
+
已完成任务战果
```

其中：

```text
任务战果
=
季度 EX
+
年度 EX
+
活动任务
+
未来扩展任务
```

说明：

* 继承战果每年 12 月末清零，不继承至次年（即每年 1 月的继承战果为 0）。
* **EX 预设任务（季常 / 年常）属于「任务战果」**，不单列来源类别，
  其归属判定与 EO 之外的其它任务一致（§4.6）。* 继承战果仅继承上月，不计更早月份。

---

# 三、战果来源

程序统一定义四类战果来源：

| 来源    | 说明                          |
| ----- | --------------------------- |
| 继承战果  | 由用户输入的月度基础战果（每年 12 月末清零）     |
| 出击战果  | DailyRecord 中记录的每日出击战果       |
| EO 战果 | 已完成 EO 自动获得（有效窗口见 4.3 战果归属边界） |
| 任务战果  | 已完成 EX、活动及其它任务自动获得          |

所有统计均应基于上述分类进行计算。

---

# 四、周期计算

## 4.1 时间标准

所有时间采用：

UTC+8

战果排名与演习每日更新两次，北京时间 02:00 与 14:00（实际统计时刻为 01:00 与 13:00）。

---

## 4.2 任务刷新边界

| 周期        | 开始时间            |
| --------- | --------------- |
| DAILY     | 每日 04:00        |
| WEEKLY    | 每周一 04:00       |
| MONTHLY   | 每月 1 日 04:00    |
| QUARTERLY | 每季度首月 1 日 04:00 |
| YEARLY    | 指定月份 1 日 04:00  |
| EVENT     | 用户手动开始与结束       |

任务刷新边界仅用于判定任务是否刷新，不得用于战果归属计算。

---

## 4.3 战果归属边界

战果归属以当月最后一日（末日）为基准，与任务刷新边界不同：

| 战果来源       | 归属区间（北京时间）                                |
| ---------- | ----------------------------------------- |
| 出击战果       | 上月末日 21:00 ～ 本月末日 21:00                  |
| EO 战果      | 上月末日 23:00 ～ 本月末日 21:00                  |
| 季常任务战果     | 前月末日 13:00 ～ 本月末日 13:00（季度首月自本月首日 04:00 起算） |
| 年常任务战果     | 前月末日 13:00 ～ 本月末日 13:00                  |
| 期间限定月常任务战果 | 前月末日 13:00 ～ 本月末日 13:00                  |

补充规则：

* 出击战果：本月末日 21:00 ～ 23:00 获得的战果计入次月。
* EO 战果：各 EO 海域血条于本月末日 23:00 复活，每月各海域仅可获取一次；本月末日 21:00 ～ 23:00 获得的 EO 战果无效。
* 任务战果：本月末日 13:00 起（至月末结束）完成的任务，其战果归属次月。
* 季常任务战果的例外：季度第三月（2、5、8、11 月）末日 13:00 起完成的季常战果不计入次月，直接失效（战果蒸发）。
* 年常任务战果与期间限定月常任务战果允许跨月叠加，同一战果月内可计入两次。
* 本月末日 21:00 为战果结算时刻，本月战果在此刻定格。

计算「剩余周期时间」「所需日均」「预测战果」时，应以对应战果来源的**归属边界**为准。

统计「已完成战果」时同样以归属边界为准：任务战果按**完成时刻**归属，不得按任务所属周期归属（见 §4.6）。

---

## 4.4 季度定义

| 季度 | 月份        |
| -- | --------- |
| 春  | 3、4、5 月   |
| 夏  | 6、7、8 月   |
| 秋  | 9、10、11 月 |
| 冬  | 12、1、2 月  |

---

## 4.5 周期解析

程序应依据当前时间自动解析：

* 当前周期
* 当前 Period ID
* 当前周期开始时间
* 当前周期结束时间
* 当前周期剩余时间
* 当前战果归属月份

任务完成状态应依据对应 Period ID 查询。

程序不得采用"重置任务"方式更新状态。

## 4.6 任务战果归属判定

任务战果（EO / EX / 活动 / 自定义）**按完成时刻归属**，每条完成记录恰好归属一个月。

判定规则：

* 归属区间为「前月末日 13:00 ～ 本月末日 13:00」（§4.3）。
* 落在区间内的完成记录计入该月；本月末日 13:00 起完成的计入次月。
* 季常例外：季度第三月（2、5、8、11 月）末日 13:00 起完成的季常战果不计入次月，直接失效。
* 完成时刻缺失时（历史数据 / 外部导入），以该任务所属周期的起算时刻代替。

**不得按「任务所属周期」归属战果。** 周期只用于判定任务是否刷新、完成状态挂在哪个
Period ID 上。跨月的周期（季常 3 个月、年常 12 个月）若按周期归属，同一条完成记录会被
它覆盖的每一个月重复计入：季常会在该季度 3 个月各计一次，年常会在该年度 12 个月各计一次。

DAILY / WEEKLY 的周期比「月」短，一个月内会出现多个周期：该月内**每一期**已完成的战果
都要计入该月。周期刷新只决定「这一期还能不能做」，不得让已经获得的战果从当月统计中消失。

规划池战果不受归属影响：它按「当前周期尚未完成」计算（§六、§七）。

---

## 4.7 完成状态判定

任务的完成状态**只保存在 TaskRecord.completed**，任何时候都不由节点进度派生而来。

不带节点的任务：完成状态完全由用户操作决定。

带节点的任务：进度与完成状态之间只有两条关联（除此之外互不影响）：

1. **节点全部达成 ⇒ 自动置为已完成。** 写入进度时同步判定，单向；完成时刻一并写入，
   供 §4.6 的战果归属使用。
2. **已完成且此刻节点全部达成 ⇒ 取消完成时一并重置进度**（记录被删除，语义为「这一轮重来」）。

其余情况一律不改动完成状态：

- 已完成但节点未全部达成时，调低进度**不**使完成状态回退，其战果仍计入已获得。
  撤销只能由用户显式取消完成。
- 取消完成时节点未全部达成 ⇒ 只把完成状态置为未完成，进度保留。

**进度本身不参与战果计算。** §4.6 的归属判定只读取完成状态与完成时刻。

---

# 五、实际战果计算

实际战果表示玩家当前已经获得的真实战果。

计算方式：

```text
实际战果
=
继承战果
+
累计出击战果
+
已完成 EO 战果
+
已完成任务战果
```

其中：

累计出击战果：

DailyRecord 全部累计。

EO 战果：

该战果归属月内已完成的 EO 战果之和（归属判定见 §4.6）。

任务战果：

该战果归属月内已完成的任务战果之和（归属判定见 §4.6）。

---

# 六、规划池

规划池用于表示：

"计划完成，但尚未完成"的任务集合。

规划池应支持：

* 单项选择
* 分类全选
* 分类取消全选
* 全部清空

规划池中的任务不得影响实际战果。

---

# 七、规划战果计算

规划战果表示：

在当前规划条件下预计可获得的总战果。

计算方式：

```text
规划战果
=
实际战果
+
规划池战果
```

其中：

规划池战果：

所有已勾选且尚未完成任务的战果总和。

已完成任务不得重复加入规划池。

---

# 八、目标计算

用户可设定当月目标战果。

目标可随时修改。

修改目标不会影响历史数据。

系统应实时计算：

* 当前目标差值
* 完成率
* 剩余目标
* 是否已达成目标

---

# 九、日均计算

系统核心口径仅提供自然日均。

自然日均定义：

```text
累计出击战果
÷
当前周期已经过天数
```

说明：

EO、EX、活动任务均不参与自然日均计算。

"当前周期已经过天数"按战果归属月计算（上月末日 21:00 ～ 当前时刻），不按任务刷新边界计算。

综合口径（可选）：

若 UI 需展示“含任务口径”的综合进度指标，必须由运行时计算生成，且不得将综合口径结果持久化保存。

---

# 十、所需日均

系统应依据：

* 当前目标
* 当前规划状态
* 剩余周期时间

实时计算：

达到目标仍需的平均每日出击战果。

其中"剩余周期时间"按战果归属边界计算（截至本月末日 21:00）。

若规划战果已达到目标。

则：

所需日均应为 0。

---

# 十一、预测计算

系统应预测：

预计当前周期结束时的总战果。

预测终点为战果归属边界（本月末日 21:00）。

默认预测方式：

最近 7 天平均出击战果。

预测方式允许用户修改。

例如：

* 最近 3 天平均
* 最近 7 天平均（默认）
* 最近 14 天平均
* 当前周期平均
* 自定义方式（预留扩展）

预测计算仅影响预测结果。

不得修改任何历史数据。

---

# 十二、剩余周期计算

程序应实时计算：

* 剩余天数
* 剩余小时
* 剩余分钟（可选）

剩余周期以战果归属边界为终点（月度即本月末日 21:00）。

同时计算：

当前规划池剩余可获得战果。

用于辅助规划。

---

# 十三、图表计算

所有图表均由当前数据实时生成。

程序不得缓存图表数据。

首页图表应展示：

* 实际战果
* 规划战果
* 目标战果

推荐采用统一颜色表示：

* 已获得战果
* 已规划战果
* 尚未完成目标

## 13.1 poi 数据接入

poi 数据来自外部战果插件，属于**采集到的原始事实**，不属于本工具的业务数据。
其快照存储定位见 docs/03_data.md §9.1。

### 13.1.1 每日建议值

从 poi 数据可换算出「每日仅出击 + 远征战果」，与本站 DailyRecord 口径一致。

换算基于相邻采样点之间的增量，并折算为本工具的战果单位。

该口径**不含 EO / 任务战果**，因此可直接作为 DailyRecord 的建议值。

换算结果**不落库、不参与统计**，仅在界面上作为建议值展示；
只有用户确认「填充空白项」后，才会写入 DailyRecord。

### 13.1.2 跨月脏数据

poi 侧的月度序列可能残留上月数据。判定规则：

> 从序列起点向后扫描，一旦出现**小于前一个值**的采样，即认定该点起为上月残留，
> 该点及之后的数据全部丢弃。

此规则用于所有按月度序列取值的地方（累计战果、战果线历史等）。

### 13.1.3 EO 完成状态

poi 侧提供的是「**尚未完成**」的海域列表，而非已完成列表。因此：

```text
已完成 EO = 系统内全部 EO 海域 − poi 侧尚未完成的海域
```

该判定**零配置**：poi 使用的海域代号与系统内置 EO 模板一一对应，无需额外映射。

### 13.1.4 战果线取值

战果线（联合 / 一群 / 二群 / 三群）取值的回退顺序：

1. 当月实时值
2. 当月已结算值
3. 月度历史序列的**末值**

说明：

* 二群线通常不存在前两类值，只能取月度历史末值。
* 各战果线按数值**降序**排列。

战果线对比图另展示一条「我的累计」线，其取值优先使用 poi 侧的权威口径，
缺失时回退为当月 DailyRecord 的逐日累计。

### 13.1.5 写入边界

同步 poi 数据**绝不自动写入业务数据**。所有写入均需用户显式操作：

* **每日记录**：同步后展示建议值，用户确认后仅填充**空白日期**，已有记录一律跳过，不覆盖。
* **任务完成状态**：仅做**单向**同步——poi 显示已完成则允许批量标记为已完成；
  反向差异（本工具已标记完成但 poi 未完成）**只作提示，不自动取消**。

反向差异不自动取消的原因：任务战果按完成时刻归属（§4.6），
而 poi 的完成列表只反映「当前血条是否存在」，
自动取消会抹掉已经计入历史归属的战果。

同步**不会自动触发**（既不在启动时执行，也无定时同步），只能由用户在界面上手动发起。
原因：程序运行于本地文件环境，浏览器安全策略禁止网页自行读取任意本地路径。
界面入口见 docs/02_ui.md。
### 13.1.6 EX 季常完成状态

EX 预设任务中只有**季常**能经 poi 同步 —— poi 侧没有年常的完成标记。

与 EO 相反，poi 侧这里给出的是每项的**完成时刻**（而不是"清单里有没有"）：

```text
已完成 EX 季常 = poi 侧该项的完成时刻非 0
```

⚠️ **范围限制**：poi 会**每个战果月**把这份清单重置为全 0
（它自己只用该字段计算当月战果增量），因此它只能回答「**当前战果月内**是否完成」，
**不覆盖本季更早的月份** —— poi 侧「未完成」并不等于本季没做过。
本工具因此**只做正向勾选**：漏判只会少勾，不会勾错。

匹配方式：poi 的季常名称与本工具的展示名**不必相同**（例如「三川」在 poi 里另有写法），
因此模板上单独保存一个 **`poiName`** 字段专门用于匹配，而不是用任务名。

说明：

* **年常（YEARLY）不参与同步**：poi 侧无对应字段，模板不写 `poiName`，天然被排除。
* **用户自建的 EX 任务不参与同步**：不带 `poiName`，同样天然被排除。
* poi 清单里出现、但本工具找不到对应任务的名字，**直接忽略**，不进入「无法匹配」提示。
* 判定依据是 poi 侧的 `zcleartslist`（每项的完成时刻，`0` 表示未完成）。
* 排除停用（`enabled: false`）的任务。

写入边界同 §13.1.5：**只做正向勾选，绝不自动取消**。
季常战果另有「季度第三月（2、5、8、11 月）末日 13:00 起完成即失效」的规则（§4.6），
该时点后勾选会直接失效，因此仍由用户确认后执行。

### 13.1.7 展示名与匹配名的区分

EX 预设任务涉及三个名称字段，用途互不相同，**不得混用**：

| 字段 | 用途 |
| --- | --- |
| `name` | 简称，用于悬停提示与内部引用。 |
| `fullName` | 游戏内完整任务名，**界面名称列显示的就是它**。 |
| `poiName` | poi 侧写法，**仅用于同步匹配**（§13.1.6）。 |

三者可能两两相同，也可能互不相同。界面显示与同步匹配是两件事，
因此不共用同一个字段。

# 十四、数据一致性

修改以下数据后：

* 每日记录
* 任务完成状态
* 月目标
* 继承战果
* 历史记录

程序均应重新计算：

* 战果
* 图表
* 日均
* 预测
* 规划
* 历史统计

保证所有页面结果一致。

# 十五、特殊情况处理

程序应支持：

* 补录历史每日记录
* 补录历史任务
* 修改已归档数据
* 删除错误记录
* 修改目标
* 修改继承战果

所有操作均应重新计算统计结果。

程序不得因当前日期阻止用户修改历史周期数据。

## 15.1 补录的入口与粒度

界面层通过「切换战果归属月」提供补录能力，无需单独的补录页面：

* 战果任务页：切换归属月后勾选即写入**该月对应周期**的 TaskRecord（EO 同为 TaskRecord）。
  DAILY / WEEKLY 一个月内有多个周期，需先选定期次；其余周期类型一个月只对应一个周期。
* 战果规划页：切换归属月后可修改该月的继承战果 / 月目标（MonthlyContext）。
* 战果记录页：日期可自由选择，天然支持补录历史 DailyRecord。

## 15.2 补录记录的完成时刻

战果归属按完成时刻判定（§4.6），而补录时真实完成时刻已不可知，只能写入一个
落在目标归属月内的近似值：

* 周期的起算时刻就在该月内（月常 / 当月内的日常周常）→ 取该周期的起算时刻
* 否则（季常 / 年常 / 跨月周常）→ 取该月 15 日 12:00

取"当月 15 日"而不是"当前时刻"，是为了避免补录被算进当前月，
或恰好撞上本月末日 13:00 的任务战果归属边界。

## 15.3 归档月份的保护

若目标月份已有 Archive，补录或修改前必须按 docs/06_data_strategy.md §4.2 要求用户显式确认，
避免无声地影响已归档月份的结果。归档快照本身不会被自动改写。

# 十六、未来扩展

计算框架应支持未来新增：

* 新战果来源
* 新任务类型
* 新预测算法
* 更多统计方式
* 更多图表分析

新增功能应尽可能复用现有计算流程，而不修改核心计算架构。
