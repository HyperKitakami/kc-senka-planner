# 数据设计（Data Design）

## 文档说明

本文档用于定义 Kancolle Senka Planner 的数据模型、数据实体及数据之间的关系。

本文档仅定义数据应保存什么，不描述界面实现及计算逻辑。

---

# 一、设计原则

## 1.1 Data First

数据结构优先于界面设计。

界面可调整，但数据结构应尽可能保持长期稳定，以保证历史数据兼容性。

---

## 1.2 保存事实，不保存计算结果

系统仅保存用户输入的数据与任务完成状态。

例如：

保存：

- 每日出击战果
- 任务完成状态
- 月度归档数据

不保存：

- 日均战果
- 预计月底战果
- 完成率
- 所需日均
- 各类统计结果

所有统计结果均应运行时计算。

---

## 1.3 数据职责单一

每项数据仅负责一种用途。

DailyRecord 仅保存每日出击战果。

任务战果由任务完成状态自动计算，不写入 DailyRecord。

---

## 1.4 模板与记录分离

任务定义（Template）与任务完成记录（Record）应完全分离。

任务模板描述任务本身。

任务记录描述某一周期内是否完成。

任何任务均不得直接保存"当前是否完成"状态。

---

## 1.5 版本兼容

所有导出数据应包含版本号（建议字段：`schemaVersion`）。

未来修改数据结构时，应支持旧版本自动迁移。

迁移失败时应提供可读错误信息，并保留原始导出文件，不得静默覆盖。

---

# 二、数据实体

系统采用以下核心数据实体。

## Config

项目配置。

负责保存：

- schemaVersion（数据结构版本号）
- 创建时间
- 最近修改时间
- 其它全局配置

---

## DailyRecord

每日记录。

负责保存：

- 日期
- 当日出击获得战果
- 备注

说明：

DailyRecord 不记录 EO、EX、活动等任务战果。

---

## TaskTemplate

任务模板。

用于定义所有任务。

包括但不限于：

- EO
- EX
- 活动任务
- 用户自定义任务

任务模板描述：

- 名称
- 战果值
- 所属任务组
- 周期类型
- 是否启用
- 是否系统任务

任务模板生命周期通常长期存在。

---

## TaskRecord

任务记录。

记录某一周期内任务完成情况。

例如：

- 2026-07 的 5-5
- 2026-Q3 的季度 EX
- 2026 年年度任务

TaskRecord 不保存任务定义。

仅保存：

- 对应模板
- 所属周期
- 完成状态
- 完成时间（可选）

---

## MonthlyContext

负责保存当月特殊参数。

例如：

- 继承战果
- 月目标
- 月备注
- 其它仅属于该月份的数据

---

## Archive

月度归档。

负责保存：

- 月份
- 最终战果
- 最终奖励区间
- 官方对应奖励线（可选）
- 与奖励线差值（可选）
- 奖励内容
- 月度备注

说明：

- Archive 用于历史归档展示与长期保存。
- 历史统计应基于历史原始记录（DailyRecord / TaskRecord / MonthlyContext）实时计算。
- 月度最终战果以当月末日 21:00 的战果结算为准。
- 排名为可选记录；战果实际计算至小数点后 2 位，战果相同时司令部等级高者排名靠前。

---

## Settings

用户设置。

例如：

- 首页布局
- 图表显示
- 默认规划方式
- 数据管理设置
- 外观设置

设置不影响历史数据。

---

# 三、数据关系

系统包含以下核心实体：

- Config
- TaskTemplate
- TaskRecord
- DailyRecord
- Archive

TaskTemplate 定义任务。

TaskRecord 保存周期内完成状态。

DailyRecord 保存每日出击战果。

Archive 保存最终归档结果。

各实体相互独立，不存在强制引用关系。

---

# 四、任务模型

所有任务均采用统一模型。

任务至少应包含以下属性：

- 名称
- 所属任务组
- 战果值
- 周期类型
- 是否启用
- 是否系统任务

程序应允许未来增加新的任务类型，而无需修改整体数据结构。

---

# 五、周期模型

所有任务均采用统一周期模型。

任务模板仅描述周期类型。

任务记录保存具体周期。

例如：

月任务：

2026-07

季度任务：

2026-Q3

年度任务：

2026

活动任务：

2026 夏季活动

系统不保存"当前任务状态"。

程序根据当前周期自动读取对应 TaskRecord。

---

# 六、周期类型（ResetCycle）

系统定义以下标准周期类型：

| 类型        | 说明    |
| --------- | ----- |
| NONE      | 不自动重置 |
| DAILY     | 每日    |
| WEEKLY    | 每周    |
| MONTHLY   | 每月    |
| QUARTERLY | 每季度   |
| YEARLY    | 每年    |
| EVENT     | 活动周期  |

所有任务均应采用上述周期类型。

---

# 七、周期定义

所有时间均采用：

UTC+8

## 7.1 任务刷新边界

任务刷新（"进入新周期"）时间：

| 周期        | 新周期开始           |
| --------- | --------------- |
| DAILY     | 每日 04:00        |
| WEEKLY    | 每周一 04:00       |
| MONTHLY   | 每月 1 日 04:00    |
| QUARTERLY | 每季度首月 1 日 04:00 |
| YEARLY    | 指定月份 1 日 04:00  |
| EVENT     | 用户手动开始与结束       |

任务刷新边界仅用于判定任务是否刷新，不得用于战果归属计算。

## 7.2 战果归属边界

战果归属以**当月最后一日（末日）**为基准，各战果来源的截止时刻不同：

| 战果来源       | 归属区间（北京时间）                                |
| ---------- | ----------------------------------------- |
| 出击战果       | 上月末日 21:00 ～ 本月末日 21:00                  |
| EO 战果      | 上月末日 23:00 ～ 本月末日 21:00                  |
| 季常任务战果     | 前月末日 13:00 ～ 本月末日 13:00（季度首月自本月首日 04:00 起算） |
| 年常任务战果     | 前月末日 13:00 ～ 本月末日 13:00                  |
| 期间限定月常任务战果 | 前月末日 13:00 ～ 本月末日 13:00                  |

补充规则：

- 出击战果：本月末日 21:00 ～ 23:00 获得的战果计入次月。
- EO 战果：各 EO 海域血条于本月末日 23:00 复活，每月各海域仅可获取一次；本月末日 21:00 ～ 23:00 获得的 EO 战果无效（仍可获得勋章等报酬）。
- 任务战果：本月末日 13:00 ～ 23:00 完成的任务，其战果归属次月。
- 季常任务战果的例外：季度第三月（2、5、8、11 月）末日 13:00 ～ 23:00 完成的季常战果不计入次月，直接失效。
- 年常任务战果与期间限定月常任务战果允许跨月叠加，同一战果月内可计入两次。
- 本月末日 21:00 为战果结算时刻，本月战果在此刻定格。
- 战果排名与演习每日更新两次，北京时间 02:00 与 14:00（实际统计时刻为 01:00 与 13:00）。

## 7.3 季度定义

| 季度 | 月份        |
| -- | --------- |
| 春  | 3、4、5 月   |
| 夏  | 6、7、8 月   |
| 秋  | 9、10、11 月 |
| 冬  | 12、1、2 月  |

## 7.4 派生计算

程序应依据上述规则计算：

- 当前周期
- 剩余周期时间（按战果归属边界，而非任务刷新边界）
- 当前周期剩余可获得任务战果
- 每条记录的战果归属月份

具体计算方式由《04_calculation.md》定义。

---

# 八、数据生命周期

DailyRecord：

长期保存。

TaskTemplate：

长期保存。

TaskRecord：

长期保存。

Archive：

长期保存。

Settings：

长期保存。

任何历史数据默认不自动删除。

活动结束后，仅结束活动周期，不删除对应历史记录。

---

# 九、数据存储

项目采用 Local First 设计。

所有数据默认保存于本地。

程序应支持：

- 自动保存
- 导出完整数据
- 导入完整数据
- 数据版本升级
- 数据恢复

数据格式由后续实现决定。

不依赖服务器或在线数据库。
